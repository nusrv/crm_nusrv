# Founding engineer self-criticism

## Executive summary

The foundation preserved useful history and provider isolation, but I let policy, transport and UI evolve at different speeds. Several safeguards were correct in isolation and still failed the product requirement at the system boundary. I would keep the architectural seams and make acceptance criteria executable earlier.

| Previous choice | What fell short | What I would do differently |
| --- | --- | --- |
| Designed automatic milestones and payment-gated fulfillment into early policy | The earlier rules were documented, but the design coupled urgency, message delivery and commercial closure. The current owner direction reveals the cost of that coupling (**A-01**). | Treat detection, policy and human commands as separate since they have different authority and rollback behavior. Pin effective policy in one release-level matrix. |
| Accepted signature-based QR checks to keep the endpoint simple | The test proves the check admits non-images. The input check did not establish what final document printability needed (**A-02**). | Define validation in terms of bounded decode and the actual output. Use synthetic corruption tests and a real render early. Reuse branding decode techniques where appropriate. |
| Built a stable Message-ID and ownership lease before addressing deferred fairness | Lease/CAS protected normal delivery, but an unchanged sort key leaves blocked jobs ahead of eligible work (**A-03**). SMTP completion still cannot be transacted with MariaDB (**A-11**). | Model next-attempt eligibility and unknown outcomes at the same time as leases. Test mixed-mailbox queues, starvation and crash windows, not only one-row happy paths. |
| Left access token revocation as a bounded consequence of stateless JWTs | This was an availability and simplicity trade-off. The design permits stale authority during the configured token lifetime, and the browser ignored the existing refresh path at HEAD (**A-04**). | Define revocation policy per action up front, and ship real browser refresh and logout tests with identity. Keep explicit expiry controls testable using a clock. |
| Focused branding tests on snapshot scope and shared rendering | I did not pin the meaning of the visible Sales Tax No. to a fixture with clearly distinct legal issuer and buyer identifiers (**A-05**). | Encode field semantics in the print contract and compare actual rendered documents throughout. A visually successful fixture can still bind the wrong taxpayer. |
| Kept separate outboxes and repeated transitional code | The behavior differences justified separate domains. The amount of duplicated lease, retry and explanation text makes it easy to change one queue while assuming both changed (**A-03**, **A-07**, **A-11**). | Share only well-tested primitives when there is proof the semantics match. Keep recipient policy, scheduling, audience and settlement of uncertain outcomes explicit by use case. |
| Built layered provider settings with increasingly detailed flags | Stored configuration, effective permission and UI sometimes tell different stories. Setting false in a resolver can leave Admin test routes and enabled-looking settings in view (**A-13**). | Model configured, diagnostically available and operationally enabled separately. Test capability combinations with runtime adapters under a common release policy. |
| Stopped the workflow implementation with cross-layer deltas | The preserved tree contains schema without migrations and partial server changes without matching UI. It is useful design work but weak release evidence (**A-01**, **A-10**). | Work in reviewable vertical slices, with contract tests and capability gating as soon as the first entry point exists. Make an explicit transition record when pausing. |
| Added shared popup markup before requiring a shared behavior contract | Forms still close after save and nesting and keyboard behavior are inconsistent (**A-09**). | Treat focus, save feedback and parent restoration as acceptance at the primitive and use-case levels. |

The historical mail and Phase 4 work did anticipate important cases: issuer isolation, retry-safe identity, migration constraints, immutable branding and affirmative actions. Keep those controls while confronting their limits. Historical test totals, staging setup and audit logs cannot substitute for an artifact-bound release check.
